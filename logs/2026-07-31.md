# G1 휴머노이드 로봇 실습 학습일지

## 1. 시뮬레이션 및 실기체 적용

먼저 시뮬레이션에서 G1의 보행과 동작 코드를 실행하여 낙상 여부와 동작 순서를 확인하였다. 이후 검증한 코드를 실제 G1 로봇에 적용하는 두 단계로 실습을 진행하였다.

시뮬레이션에서 정상적으로 실행되더라도 실기체에서는 네트워크 연결과 로봇의 현재 제어 모드를 추가로 확인해야 했다.

## 2. 실기체 연결 및 통신 확인

노트북과 G1을 유선 랜으로 연결하고 두 장치의 IP 주소가 같은 네트워크 대역에 있는지 확인하였다. 이후 유선 네트워크 인터페이스를 코드에 지정하고, `ping`과 모니터링 프로그램을 이용하여 로봇의 상태 데이터가 정상적으로 수신되는지 확인하였다.

단순히 랜선을 연결하는 것만으로는 동작하지 않았으며, 다음과 같은 과정이 필요했다.

- 유선 네트워크 인터페이스와 IP 주소 확인
- G1의 IP 주소로 통신 여부 확인
- 코드 실행 시 올바른 인터페이스 지정
- 모니터링 프로그램에서 로봇 상태 수신 확인
- 실제 동작 전 행어, 비상 `Damp` 및 주변 안전 상태 확인

## 3. 제어 모드 전환

G1은 어느 상태에서나 바로 동작 명령을 수행하는 것이 아니라 다음과 같은 제어 단계를 순서대로 거쳐야 했다.

`Damp → Squat2StandUp 또는 StandUp → Start`

먼저 `Damp` 상태에서 안전하게 대기한 후 기립 모드로 전환하고, 기립이 완료되면 `Start` 모드로 진입해야 상체 동작을 수행할 수 있었다. 중간 단계를 생략하거나 기립 및 균형 제어가 활성화되지 않은 상태에서 명령을 보내면 동작이 실행되지 않았다.

또한 로봇의 펌웨어에 따라 같은 모드라도 사용하는 FSM 번호가 달랐다. 코드에 설정된 번호와 실제 로봇의 모드 번호가 맞지 않아서 전환 명령이 수행되지 않은 것 같다, 실제 로봇에 맞는 FSM 번호로 변경한 후 정상적으로 동작할 것으로 예상된다.

## 4. 팔 동작 실행

`g1_real_sequence.py`에서 `wave`와 `hands_up` 두 동작을 설정하고 `--arm-only` 옵션을 사용하여 팔 동작만 시험하였다. 실행 결과 `hands_up` 동작은 정상적으로 수행되었지만 `wave`는 실행되지 않았다.

코드를 확인해 보니 `hands_up`은 직접적인 팔 관절 제어 명령으로 연결되어 있었지만, `wave`는 팔 동작처럼 보이더라도 locomotion API의 `WaveHand()` 명령으로 연결되어 있었다. 따라서 팔 동작만 실행하는 `--arm-only` 옵션에서는 `wave`가 제외되고 `hands_up`만 실행되었다.

## 5. 학습 내용

이번 실습을 통해 시뮬레이션에서 코드를 먼저 검증한 뒤 실기체에 적용해야 한다는 것을 배웠다. 또한 실제 휴머노이드 로봇은 IP 통신만 연결한다고 바로 움직이는 것이 아니라, 로봇 상태를 확인하고 `Damp`, 기립, `Start` 모드를 순서대로 거쳐야 한다는 점을 알게 되었다.

동작이 실행되지 않을 때는 코드 오류뿐만 아니라 네트워크 인터페이스, FSM 모드 번호, 현재 제어 상태와 실행 옵션까지 함께 확인해야 한다.
